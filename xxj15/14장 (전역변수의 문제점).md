#  14장 - 전역 변수의 문제점
*전역 변수의 무분별한 사용은 위험하다. 전역 변수를 반드시 사용해야 할 이유를 찾지 못한다면 지역 변수를
사용해야 한다.*

*근데 여기에서 얘기하는건 주로 var 기준임을 생각하며 읽자*

## 📍 14.1 변수의 생명 주기 
### 1.1 지역 변수의 생명 주기 
- **변수의 생명주기** : 변수는 선언에 의해 생성되고 할당을 통해 값을 갖고, 언젠가 소멸한다. 
  - 변수에 생명 주기가 없다면 한 번 선언된 변수는 프로그램 종료시까지 영원히 메모리 공간을 점유해 .. 

```js
function foo() {
  var x = 'local';
  console.log(x); // local
  return x; // return x;를 마치고 함수가 끝나면, 자바스크립트 엔진은 "이 함수의 임무가 끝났다"고 판단하여 함수 내부의 지역 변수 x를 메모리에서 즉시 삭제(가비지 컬렉션 대상)해 버린다.
}

foo();
console.log(x); // ReferenceError: x is not defined
```

- **지역 변수의 생명 주기는 함수의 생명 주기와 일치한다.** 
  - *함수가 실행될 때 태어나고, 함수가 종료되면 죽는다.*

> Q) [변수 호이스팅 파트]  "변수 선언은 선언문이 어디에 있든 상관
없이 가장 먼저 실행된다. 다시 말해, 변수 선언은 코드가 한 줄씩 순차적으로 실행되는 시점인 런타임에 실행되는 것이 아니라 런타임 이전 단계에서 자바스크립트 엔진에 의해 먼저 실행된다" 고 하지 않았나요? 

A) 위 설명은 전역 변수 한정 !! 

| 구분 | 호이스팅(선언) 시점 | 설명 |
| :--: | :--: | :--: |
| **전역 변수** | 애플리케이션 실행 직후 | 자바스크립트 엔진이 코드를 한 줄씩 읽기(런타임) 전, 전역 스코프를 먼저 훑으며 실행됨. |
| **지역 변수** | 함수가 호출된 직후 | 함수가 호출되어 함수 몸체 코드가 실행되기 전, 해당 함수 스코프 내의 선언문들을 먼저 실행함. |

- 변수의 생명주기 : 메모리 공간이 확보된 시점부터 메모리 공간이 해제되어 가용 메모리 풀에 반환되는 시점까지

```js
var x = 'global';

function foo() {
  console.log(x); // 값은 ? 
  var x = 'local';
}

foo();
console.log(x); // global
```

> 함수 내부 `console.log(x)` 결과 `undefined`가 나온다. 
- **함수가 호출된 직후 발생하는 지역 변수 호이스팅** 때문. 
**일어나는 과정**
1. **호출 직후 (런타임 이전)**: foo()가 호출되면 엔진은 함수 내부를 슥 훑는다. `var x`를 발견하고는 함수 스코프 최상단으로 끌어올려(호이스팅) `undefined`로 초기화.

2. **한 줄씩 실행 (런타임)**: `console.log(x)`를 실행하는 시점에, 이미 함수 지역 스코프에는 호이스팅된 `x`가 존재함.

3. **결과**: 엔진은 외부의 `'global'`을 찾으러 나가지 않고, 자기 방에 있는 (아직 값이 할당되지 않은) x를 참조하여 `undefined`를 출력.

- **호이스팅은 스코프를 단위로 동작한다.** 
  - 전역 변수 호이스팅은 전역 변수의 선언이 전역 스코프의 선두로 끌어올려진 것처럼, 지역 변수의 호이스팅은 지역 변수의 선언이 지역 스코프의 선두로 끌어 올려진 것처럼 동작..

> 호이스팅은 변수 선언이 스코프의 선두로 끌어올려진 것처럼 동작하는 JS 고유의 특징을 말한다. 

### 1.2 전역 변수의 생명 주기 
- var 키워드로 선언한 전역 변수의 생명 주기는 전역 객체의 생명 주기와 일치한다. 
  - 브라우저 환경에서 전역 객체는 `window` 이므로 브라우저 환경에서  `var` 키워드로 선언한 전역 변수는 전역 객체 `window`의 프로퍼티이다. 

## 📍 14.2 전역 변수의 문제점 
### 암묵적 결합 
- 전역 변수는 모든 코드가 어디서든 전역 변수를 참조하고 변경할 수 있는 **암묵적 결합**을 허용한다. 
  - 변수의 유효 범위가 커질수록 의도치 않게 상태가 변경될 수 있는 위험성이 커진다

### 긴 생명 주기 
- **전역 변수는 생명 주기가 길다.** 
  - 메모리 리소스도 오랜 기간 소비하고, 전역 변수의 상태 변경할 수 있는 시간도 기회도 많다

### 스코프 체인 상에서 종점에 존재 
- 변수를 검색할 때 전역 변수가 가장 마지막에 검색되기 때문에 **검색 속도가 가장 느리다.** 

### 네임스페이스 오염 
- JS는 파일이 분리되어 있어도 하나의 전역 스코프를 공유한다. 따라서 다른 파일내에서 동일한 이름으로 명명된 전역 변수/함수가 같은 스코프 내에 존재해 문제가 발생할 수 있다.

> ES6 모듈 : 파일 하나가 자신만의 스코프를 가지게 되어, 파일끼리 변수 이름 겹칠 걱정이 사라짐!

## 📍 14.3 전역 변수의 사용을 억제하는 방법 
- 전역 변수를 반드시 사용해야 할 이유를 찾지 못한다면 지역 변수를 사용해야 한다. **변수의 스코프는 좁을수록 좋다.**

### 1. 즉시 실행 함수 
- 함수 정의와 동시에 즉시 호출되는 함수. 딱 한 번만 실행되고 다시는 호출할 수 없다. 
```js
(function () {
  var foo = 10; // 즉시 실행 함수의 지역 변수
  // ...
}());

console.log(foo); // ReferenceError: foo is not defined
```

- 추가 정보) 이걸 왜쓰나 궁금해서 찾아봤는데,  

옛날엔 
```js
for (var i = 0; i < 3; i++) {
  (function (currentI) { // i 값을 즉시 복사해서 가둠
    setTimeout(function () {
      console.log(currentI); // 0, 1, 2가 정상 출력됨
    }, 100);
  }(i));
}
```
이런식으로 사용하면서 반복문 아에서 비동기 작업 하면 변수 값이 꼬이는 문제점이 있었는데, 이를 해결하기 위해 즉시 실행 함수 썼다고 한다. 

- 추가 정보) 요즘은 IIFE를 많이 쓰지 않는다. 
 1. `let, const`: 블록 레벨 스코프가 생겨서 if나 for 문 안에서 변수를 쉽게 가둘 수 있다
2. ES6 모듈(Module): 파일 하나가 자신만의 스코프를 가지게 되어, 파일끼리 변수 이름이 겹칠 걱정이 사라짐


### 2. 네임스페이스 객체 
- 전역 스코프에 너무 많은 변수를 선언하면 이름이 겹칠 확률이 높기 때문에, MYAPP 같은 거대한 '상자(객체)'를 하나 만들어 관리하는 방식이다. 
  - 하지만 객체 자체가 여전히 전역 변수이기 때문에 완벽한 해결책 XX 
```js
var MYAPP = {}; // 전역 네임스페이스 객체

MYAPP.person = {
  name: 'Lee',
  address: 'Seoul'
};

console.log(MYAPP.person.name); // Lee
```

### 3. 모듈 패턴
- 모듈 패턴은 추후 24장 "클로저"에서 자세히 살펴본 후 이해하도록 하자 .. 

- 모듈 패턴은 전역 네임스페이스의 오염을 막고 정보 은닉을 구현하는데 사용된다 

```js
var Counter = (function () {
  // private 변수
  var num = 0;

  // 외부로 공개할 데이터나 메서드를 프로퍼티로 추가한 객체를 반환한다.
  return {
    increase() {
      return ++num;
    },
    decrease() {
      return --num;
    }
  };
}());

// private 변수는 외부로 노출되지 않는다.
console.log(Counter.num); // undefined

console.log(Counter.increase()); // 1
console.log(Counter.increase()); // 2
console.log(Counter.decrease()); // 1
console.log(Counter.decrease()); // 0
```

- 클로저의 맛보기 느낌 
  1. var num은 즉시 실행 함수 내부의 지역 변수 - 함수 밖에서는 절대 직접 접근할 수 없으므로 Counter.num은 undefined가 뜬다.
  2. 기능 제공: 하지만 increase()와 decrease() 메서드는 자신이 태어난 환경(함수 내부)을 기억하고 있어서, num 변수를 마음대로 조절 가능!
  3. 상태 유지: 함수는 이미 실행되고 끝났지만, num이라는 값은 메모리에 남아 Counter 객체를 통해 계속 업데이트된다

### 4. ES6 모듈

- **ES6 모듈은 파일 자체의 독자적인 모듈 스코프를 제공한다.** 
  - 모듈 내에서 `var` 키워드로 선언한 변수는 더는 전역 변수가 아니며 `window` 객체의 프로퍼티도 아니다. 

> type="module"을 사용하면 파일끼리 변수 이름이 겹쳐도 서로 영향을 주지 않는다! 

#### 추가 내용 
*리액트 개발을 할 때 우리가 늘 쓰는 import와 export 문법이 바로 이 ES6 모듈(ESM) 시스템을 기반으로 작동한다* 

> 리액트는 거대한 앱을 수십, 수백 개의 컴포넌트(.js, .jsx 파일)로 쪼개서 만든다. 이때 type="module"과 같은 모듈 시스템이 없다면 ??

- `Header.js`에도 `const data = ...`가 있고, `Footer.js`에도 `const data = ..`.가 있다면 전역 스코프에서 충돌 발생 

**=> 모듈 시스템을 통해 각 파일에 모듈 스코프를 줌 !**

```jsx
// Header.js
const title = "Header 부분"; // 이 파일 안에서만 유효!
export default title;

// Footer.js
const title = "Footer 부분"; // 이름이 겹쳐도 상관없음!
export default title;

// App.js
import HeaderTitle from './Header';
import FooterTitle from './Footer';
```

- 리액트 빌드 도구 (Webpack, Vite 등)가 최종적으로 만들어내는 HTML 결과물을 보면 아래와 같이 되어있을 것이다. 결국, 리액트는 **모듈의 집합** 이라고 생각하면 된다. 
```html
<script type="module" src="/src/main.jsx"></script>
```
