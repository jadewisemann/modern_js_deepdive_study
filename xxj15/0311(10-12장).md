## 📍 10장 : 객체 리터럴

### 1. 객체란?

- JS는 객체 기반 프로그래밍 언어이며, JS를 구성하는 거의 **모든 것**이 객체이다.
  - 원시값을 제외한 나머지 (함수, 배열, 정규 표현식 등)

⚡️ **원시타입 vs 객체 타입**

- 원시 타입 :
  1. 단 하나의 값만 나타냄
  2. 변경 불가능 (immutable value)

- 객체 타입
  1. 다양한 타입의 값을 하나의 단위로 구성한 복합적인 자료구조
  2. 변경 가능 (mutable value)

#### 🌱 객체란

: 0개 이상의 프로퍼티로 구성된 집합이며, 프로퍼티는 key와 value로 구성된다.

```js
var person = {
  name: "Lee", // 프로퍼티 - key : name, value : 'Lee'
  age: 20,
};
```

- js에서 사용할 수 있는 모든 값은 프로퍼티 value가 될 수 있다.
  - js에서는 함수도 일급 객체이므로 값으로 취급할 수 있는데, 프로퍼티 값이 함수일 경우, 일반 함수와 구분하기 위해 **메서드** 라고 부른다.

```js
var counter = {
  num: 0,
  increase: function () {
    this.num++;
  },
};
```

- 위 객체에서 `num: 0` 은 프로퍼티, `increase: function(){
  this.num++;
}`는 메서드이다.
  - **프로퍼티** : 객체의 상태를 나타내는 값(data)
  - **메서드** : 프로퍼티를 참조하고 조작할 수 있는 동작

✨ 객체는 **객체의 상태를 나타내는 값(프로퍼티)**과 **프로퍼티를 참조하고 조작할 수 있는 동작(메서드)**을 모두 포함할 수 있기 때문에 상태와 동작을 하나의 단위로 구조화할 수 있어서 유용하다.

- 객체의 집합으로 프로그램을 표현하려는 프로그래밍 패러다임을 객체지향 프로그래밍이라고 한다. (19절 객체지향 프로그래밍에서 계속 .. )

### 2. 객체 리터럴에 의한 객체 생성

- C++나 자바 같은 클래스 기반 객체지향 언어는 클래스를 사전에 정의하고 필요한 시점에 `new` 연산자와 함께 생성자를 호출하여 인스턴스를 생성하는 방식으로 객체를 생성한다.
  - 인스턴스 : 클래스에 의해 생성되어 메모리에 저장된 **실체**. 객체지향 프로그래밍에서 객체는 **클래스 + 인스턴스** 포함한 개념.

- **JS** : 프로토타입 기반 객체지향 언어, 다양한 객체 생성 방법을 지원함
- 객체 리터럴
- Object 생성자 함수
- 생성자 함수
- Object.create 클래스

그 중 대표적인 것이 **객체 리터럴**

#### ⚡️ 객체 리터럴

```js
// 예제 10-01
var person = {
  name: "Lee",
  sayHello: function () {
    console.log(`Hello! My name is ${this.name}.`);
  },
};

console.log(typeof person); // object
console.log(person); // {name: "Lee", sayHello: f}
```

- 중괄호 내에 프로퍼티를 정의하지 않으면 빈 객체가 생성된다.

```js
// 예제 10-02
var empty = {}; // 빈 객체
console.log(typeof empty); // object
```

💥 **객체 리터럴의 중괄호는 코드 블럭을 의미하지 않는다!** 코드 블럭을 닫는 중괄호는 `;`를 붙이지 않지만, 객체 리터럴은 값으로 평가되는 표현식이기 때문에 `;`이 필요하다.

### 3. 프로퍼티

> **객체는 프로퍼티의 집합이며, 프로퍼티는 키와 값으로 구성된다. **

```js
var person = {
  name: "Lee",
  age: 20,
};
```

- 프로퍼티를 나열할 때는 쉼표로 구분한다
- 프로퍼티의 키와 값으로 사용할 수 있는 값
  - key: 빈 문자열을 포함하는 모든 **문자열** 또는 **심벌 값**
    - 반드시 식별자 네이밍 규칙을 따라야 하는 것은 아니다. 하지만, 식별자 네이밍 규칙을 따르지 않는 이름에는 **반드시 따옴표를 사용**해야 한다.
    - 하지만, 이왕이면 식별자 네이밍 규칙에 위배되는 프로퍼티 이름이나 빈 문자열이나 예약어를 사용하지 않도록 하자 ..
    - 프로퍼티 키에 문자열이나 심벌값 외의 값을 사용하면 **암묵적 타입 변환을 통해 문자열이 된다.**
  - value: JS에서 사용할 수 있는 **모든 값**

### 4. 메서드

- JS함수는 객체(일급객체) 이므로 프로퍼티 값으로 사용할 수 있고, 프로퍼티 값이 함수일 경우 일반 함수와 구별하기 위해 메서드라고 부른다.

💡 정리하면, 메서드는 **객체에 묶여 있는 함수**를 의미한다.

```js
// 예제 10-11
var circle = {
  radius: 5, // ← 프로퍼티

  // 원의 지름
  getDiameter: function () {
    // ← 메서드
    return 2 * this.radius; // this는 circle을 가리킨다.
  },
};

console.log(circle.getDiameter()); // 10
```

- 메서드 내부에서 사용한 `this 키워드`는 객체 자신 (위 예제에서는 circle 객체)을 가리키는 참조변수이다. (22장에서 계속)

### 5. 프로퍼티 접근

프로퍼티에는 다음 두 가지 방식으로 접근할 수 있다.
프로퍼티 키가 식별자 네이밍 규칙을 준수하면 두 가지 방식 모두 사용해 접근할 수 있다.

- **마침표 표기법** : 마침표 프로퍼티 접근 연산자(`.`) 사용
- **대괄호 표기법** : 대괄호 프로퍼티 접근 연산자(`[...]`) 사용
  - 프로퍼티 키가 식별자 네이밍 규칙을 준수하지 않으면 반드시 대괄호 표기법을 사용해야 한다.

```js
// 예제 10-12
var person = {
  name: "Lee",
};

// 마침표 표기법에 의한 프로퍼티 접근
console.log(person.name); // Lee

// 대괄호 표기법에 의한 프로퍼티 접근
console.log(person["name"]); // Lee

console.log(person[name]); // Reference Error
console.log(person.age); // undefined
```

- 대괄호 표기법을 사용하는 경우 **대괄호 프로퍼티 접근 연산자 내부에 지정하는 프로퍼티 키는 반드시 따옴표로 감싼 문자열**이어야 한다.

```js
// 예제 10-15
var person = {
  'last-name': 'Lee',
  1: 10
};

person.'last-name';   // → SyntaxError: Unexpected string
person.last-name;     // → 브라우저 환경: NaN
                      // → Node.js 환경: ReferenceError: name is not defined

person[last-name];    // → ReferenceError: last is not defined
person['last-name'];  // → Lee
```

#### ❓ 퀴즈 `person.last-name;` 의 실행 결과가 브라우저 환경이랑 Node.js 환경에서 서로 다른 이유?

1. js엔진은 `person.last-name`을 프로퍼티 접근으로 보지 않고 `person.last - name`처럼 해석한다.
1. `person.last` 평가 -> person객체에 `last` 프로퍼티 없음 -> `undefined`
1. `undefined - name` 처럼 뺄셈 연산으로 해석됨

1. **Node.js**에서는 `name` 변수가 선언되어 있지 않으니까 -> `ReferenceError: name is not defined`
1. **브라우저**에서는 `window.name` 이라는 전역변수 `name` 이 존재. (기본값 = `""` )
   - 계산은 `undefined - ""` -> 숫자 변환 발생 -> **NaN**

### 6. 프로퍼티 값 갱신

- 이미 존재하는 프로퍼티에 값 할당하면 프로퍼티의 값이 갱신된다.

### 7. 프로퍼티 동적 생성

- 존재하지 않는 프로퍼티에 값을 할당하면 **프로퍼티가 동적으로 생성되어 추가되고 프로퍼티 값이 할당**된다.

```js
var person = {
  name: "LEE",
};

person.age = 20;

console.log(person); // {name: 'LEE', age: 20}
```

### 8. 프로퍼티 삭제

- `delete` 연산자는 객체의 프로퍼티를 삭제한다.
  - 존재하지 않는 프로퍼티를 삭제하면 아무런 에러 없이 무시된다.

```js
var person = {
  name: "LEE",
  age: 30,
};

delete person.age;

delete person.address; // 에러발생x 무시

console.log(person); // {name: 'LEE'}
```

### 9. ES6에서 추가된 객체 리터럴의 확장 기능

#### 1. 프로퍼티 축약 표현

```js
// 예제 10-19
// ES5
var x = 1,
  y = 2;

var obj = {
  x: x,
  y: y,
};

console.log(obj); // {x: 1, y: 2}
```

- ES6에서는 프로퍼티 값으로 변수를 사용하는 경우, 변수 이름과 프로퍼티 키가 동일하면 프로퍼티 키를 생략할 수 있다.
  - 프로퍼티 키는 변수 이름으로 자동 생성된다.

```js
// 예제 10-20
// ES6
let x = 1,
  y = 2;

// 프로퍼티 축약 표현
const obj = { x, y };

console.log(obj); // {x: 1, y: 2}
```

#### 2. 계산된 프로퍼티 이름

```js
// ES5
var prefix = "prop";
var i = 0;

var obj = {};

// 계산된 프로퍼티 이름으로 프로퍼티 키 동적 생성
obj[prefix + "-" + ++i] = i;
obj[prefix + "-" + ++i] = i;
obj[prefix + "-" + ++i] = i;

console.log(obj); // {prop-1: 1, prop-2: 2, prop-3: 3}
```

- 문자열 또는 문자열로 타입 변환할 수 있는 값으로 평가되는 표현식을 사용해 프로퍼티 키를 동적으로 생성할 수 있는데, ES5dㅔ서 ES6로 변화하며 ES6에서는 **객체 리터럴 내부에서도 계산된 프로퍼티 이름으로 프로퍼티 키를 동적 생성**할 수 있다.

```js
// ES6
const prefix = "prop";
let i = 0;

// 객체 리터럴 내부에서 계산된 프로퍼티 이름으로 프로퍼티 키를 동적 생성
const obj = {
  [`${prefix}-${++i}`]: i,
  [`${prefix}-${++i}`]: i,
  [`${prefix}-${++i}`]: i,
};

console.log(obj); // {prop-1: 1, prop-2: 2, prop-3: 3}
```

#### 3. 메서드 축약 표현

```js
// ES5
var obj = {
  name: "Lee",
  sayHi: function () {
    console.log("Hi! " + this.name);
  },
};

obj.sayHi(); // Hi! Lee
```

- ES6에서는 메서드를 정의할 때 `function` 키워드를 생략한 축약 표현을 사용할 수 있다.

```js
// ES6
const obj = {
  name: "Lee",
  // 메서드 축약 표현
  sayHi() {
    console.log("Hi! " + this.name);
  },
};

obj.sayHi(); // Hi! Lee
```

- 메서드 축약 표현으로 정의한 메서드는 프로퍼티에 할당한 함수와 다르게 동작하는데 .. (이는 26.2절에서 계속 .. )

## 📍 11장 : 원시 값과 객체의 비교

**개괄 - 원시 타입 vs 객체 타입**

1. **변경 가능 여부**: 원시 값은 변경 불가능한 값(immutable)이지만, 객체는 변경 가능한 값(mutable)이다.
2. **저장 방식**: 변수에 할당할 때 원시 값은 실제 값이 저장되고, 객체는 그 객체가 위치한 메모리 주소인 참조 값이 저장된다.
3. **전달 방식**: 다른 변수에 할당할 때 원시 값은 값에 의한 전달(pass by value)로 값이 복사되지만, 객체는 참조에 의한 전달(pass by reference)로 주소값이 복사된다.

### 1. 원시 값

#### 1.1 변경 불가능한 값

- 한 번 생성된 원시 값은 **읽기 전용 값**으로서 변경할 수 없다.(**불변성 immutability**)
  - 여기서 **변경 불가능하다**는 것은 변수가 아니라 **값**에 대한 진술이다.
  - 변수는 언제나 재할당을 통해 변수 값을 변경할 수 있다.

- 변수의 상대 개념인 **상수**는 재할당이 금지된 변수를 말한다. 상수와 **변경 불가능한 값**을 동일시하지 않도록 해야한다.

- 변수에 재할당이 이뤄지면, 변수는 새롭게 재할당한 원시 값을 기리키고, 이때 변수가 참조하던 메모리 공간의 주소가 바뀐다.
  - 불변성을 갖는 원시값을 할당한 변수는 **재할당 이외에 변수 값을 변경할 수 있는 방법이 없다.**

#### 1.2 문자열과 불변성

- JS에서 문자열은 원시 타입이며, 변경 불가능하다
- 문자열은 유사 배열 객체이면서 이터러블이기 때문에 배열과 유사하게 각 문자에 접근할 수 있지만,
- 이미 생성된 문자열의 일부 문자를 변경해도 반영되지 않는다.

```js
var str = "string";
console.log(str[0]); // s

srt[0] = "S";
console.log(str); // string
```

#### 1.3 값에 의한 전달

```js
var score = 90;
var copy = score;

console.log(score, copy); // A) 90, 90

score = 100; // 변수 재할당

console.log(score, copy); // 100, 90;
```

-(A) `score` 변수와 `copy` 변수의 값 90은 다른 메모리 공간에 저장된 별개의 값이다.

- 따라서 어느 한쪽에서 재할당을 통해 값을 변경하더라도 서로 간섭 불가

⚡️ **값에 의한 전달**이라는 용어는 js를 위한 용어가 아니기 때문에 오해가 있을 수 있다. 엄격하게 말하면 변수에는 값이 아닌 메모리 주소가 전달되기 때문인데, 이는 변수와 같은 식별자는 값이 아니라 메모리 주소를 기억하고 있기 때문!

### 2. 객체

- 객체는 프로퍼티 개수가 정해져있지 않으며, 동적으로 추가되고 삭제할 수 있다.
- 프로퍼티의 값에도 제약이 없다
  ✅ 따라서 객체는 원시 값과 같이 확보해야 할 메모리 공간의 크기를 사전에 정해둘 수 없다.

#### 1. 변경 가능한 값

- 객체(참조) 타입의 값, 즉 객체는 **변경 가능한 값이다**
  - 원시 값과 달리 객체를 할당한 변수는 **재할당 없이 객체를 직접 변경 가능**하다.

- 원시 값을 할당한 변수는 원시 값 자체를 값으로 갖는 반면, 객체를 할당한 변수가 기억하는 메모리 주소를 통해 메모리 공간에 접근하면 **참조 값**에 접근할 수 있다.

✅ **참조 값 : 생성된 객체가 저장된 메모리 공간의 주소, 그 자체**

- 객체를 생성하고 관리하는 방식은 매우 복잡하며 비용이 많이 든다.
- 메모리를 효율적으로 사용하기 위해, 그리고 객체를 복사해 생성하는 비용을 절약하기 위해 객체는 변경 가능한 값으로 설계되어 있는데,,

💥 이러한 구조적 단점에 따른 부작용이 있다. 원시 값과는 다르게 **여러 개의 식별자가 하나의 객체를 공유할 수 있다.**

- 얕은 복사와 깊은 복사

```js
// 얕은 복사
const o = { x: 1 };
const c2 = o;
console.log(c2 === o); // True
```

#### 2. 참조에 의한 전달

```js
var person = {
  name : 'Lee';
};

var copy = person;
```

- 위 과정을 **참조에 의한 전달** 이라고 한다. (얕은 복사)
  - 객체를 가리키는 변수를 다른 변수에 할당하면 원본의 참조 값이 복사되어 전달된다.
    ✅ **참조 값 : 생성된 객체가 저장된 메모리 공간의 주소, 그 자체**

- 원본 `person` 과 사본 `copy`는 저장된 메모리 주소는 다르지만 동일한 참조 값을 갖는다.
  이는 두 개가 모두 동일한 객체를 가리킨다는 뜻이자, **두 개의 객체가 하나의 객체를 공유**한다는 것을 의미한다.

- **person과 copy 어느 한 쪽에서 객체를 변경하면 서로 영향을 주고받는다.**

📍 값에 의한 전달과 참조에 의한 전달은 식별자가 기억하는 메모리 공간에 저장되어 있는 값을 복사해서 전달한다는 면에서 동일하다.

- 차이 : **변수에 저장되어 있는 값이 원시 값이냐 참조 값이냐**
  -> JS에서는 _참조에 의한 전달은 존재하지 않고 값에 의한 전달만이 존재한다고 할 수 있다._
  - 포인터가 존재하는 다른 프로그래밍 언어의 '참조에 의한 전달'과 의미 일치 XX

## 📍 12장 : 함수

### 1. 함수란?

- 프로그래밍 언어의 함수 : **일련의 과정을 문(statement)로 구현하고 코드 블록으로 감싸서 하나의 실행 단위로 정의**한 것.

- 매개변수(parameter), 인수(argument), 반환 값(return value)을 가짐.
- 함수 정의 & 함수 호출 과정이 필요

### 2. 함수를 사용하는 이유

- 함수는 몇 번이든 호출할 수 있으므로 **코드의 재사용** 측면에서 매우 유용하다.
  - 유지보수의 편의성, 코드의 신뢰성, 코드의 가독성 향상에 좋음

### 3. 함수 리터럴

- **JS 함수는 객체 타입의 값**이다. 따라서 숫자 값을 숫자 리터럴로 생성하든 함수도 함수 리터럴로 생성할 수 있다.

```js
var f = function add(x, y) {
  return x + y;
};
```

- 구성요소
  - `function` 키워드
  - 함수 이름
  - 매개변수 목록
  - 함수 몸체

✅ 일반 객체는 호출할 수 없지만 함수는 호출할 수 있다

### 4. 함수 정의

_함수를 정의할 수 있는 네 가지 방법이 있다._

#### 1. [함수 생성방법 1]**함수 선언문**

```js
function add(x, y) {
  return x + y;
}
```

1. 함수 리터럴과 형태가 동일하나, 함수 선언문은 **함수 이름 생략 불가** (함수 리터럴은 가능)
2. 함수 선언문은 **표현식이 아닌 문**이다. (console에서 함수 선언문 실행하면 `undefined` 출력됨)

- 자바스크립트 엔진은 함수 선언문을 해석할 때 **함수 객체를 생성**하고, 그 함수를 호출할 수 있도록 함수 이름과 동일한 식별자를 암묵적으로 만들어 함수 객체를 할당한다.
  - 이유: 함수 이름은 함수 몸체 내부에서만 유효한 식별자니까 함수 이름과 별도로 생성된 함수 객체가 필요함!

✅ **함수는 함수 이름으로 호출하는 것이 아니라 함수 객체를 가리키는 식별자로 호출함.**

- 간단하게, JS엔진은 함수 선언문을 함수 표현식으로 변환해 함수 객체를 생성한다고 생각할 수 있음.

```js
var add = function add(x, y) {
  // 앞의 add는 식별자 뒤의 add는 함수 이름
  return x + y;
};

console.log(add(2, 5)); // add는 식별자 , 결과는 7
```

#### 2. [함수 생성방법 3]**함수 표현식**

```js
var add = function (x, y) {
  return x + y;
};
```

- JS 함수는 값처럼 변수에 할당할 수도 있고, 프로퍼티 값이 될 수도 있으며, 배열의 요소가 될 수 있다.
  - 이처럼 값의 성질을 갖는 객체를 **일급 객체**라고 하고, **JS 함수는 일급 객체다.**

- 함수 선언문과 함수 표현식이 언뜻 비슷해보일 수 있지만, 둘의 동적이 정확히 같은 것도 아니고, 함수 선언문은 **표현식이 아닌 문**이고, 함수 표현식은 **표현식인 문**이다.

#### 3. 함수 생성 시점과 함수 호이스팅

```js
// 함수 참조
console.dir(add); // ƒ add(x, y)
console.dir(sub); // undefined

// 함수 호출
console.log(add(2, 5)); // 7
console.log(sub(2, 5)); // TypeError: sub is not a function

// 함수 선언문
function add(x, y) {
  return x + y;
}

// 함수 표현식
var sub = function (x, y) {
  return x - y;
};
```

📍 **함수 선언문 vs 함수 표현식**

- **함수 선언문**: 런타임 이전에 엔진에 의해 먼저 실행되어 함수 객체가 생성됨. 덕분에 선언문 이전에 함수를 호출 가능.
- **함수 표현식**: `var foo = function() {}` 형태로 변수에 할당. 변수 선언과 동일하게 취급되어 런타임에 평가됨. 선언문 이전에 호출하면 에러가 발생하거나 사용할 수 없음.

📍 **함수 호이스팅** : 함수 선언문이 코드의 선두로 끌어 올려진 것처럼 동작하는 JS 고유의 특징

| 구분          | 함수 선언문 (`function`)      | 변수 선언 (`var`)                    |
| :------------ | :---------------------------- | :----------------------------------- |
| **공통점**    | 런타임 이전에 식별자를 생성함 | 런타임 이전에 식별자를 생성함        |
| **초기화 값** | **함수 객체**로 즉시 초기화   | **`undefined`**로 초기화             |
| **결과**      | 선언 전 호출 **가능**         | 선언 전 참조 시 **`undefined`** 반환 |

- 함수 표현식으로 함수를 정의하면 **함수 호이스팅이 발생하는 것이 아니라 변수 호이스팅이 발생**

#### 4. [함수 생성방법 3]**Function 생성자 함수**

_이 방법은 일반적이지 않고 바람직하지 않다~_

```js
var add = new Function("x", "y", "return x+y");
```

- js가 기본 제공하는 빌트인 함수인 `Function` 생성자 함수에 매개변수 목록과 함수 몸체를 문자열로 전달하면서 `new` 연산자와 함께 호출하면 함수 객체를 생성해서 반환한다.
  - `new` 연산자 없이 호출해도 결과는 동일

#### 5. [함수 생성방법 4]**화살표 함수(ES6)**

```js
var add = (x, y) => x + y;
```
