# 13장 : 스코프

## 13.1 스코프란? 
*스코프 = 유효 범위*
- 모든 식별자(변수 이름, 함수 이름, 클래스 이름 등)는 자신이 선언된 위치에 의해 다른 코드가 식별자 자신을 참조할 수 있는 유효 범위가 결정된다. 이를 **스코프**라고 하며, 스코프는 **식별자가 유효한 범위**를 말한다. 


#### 식별자 결정

```js
var x = 'global';

function foo() {
  var x = 'local';
  console.log(x); // ① 
}

foo();

console.log(x); // ②
```

- JS 엔진은 스코프를 통해 **어떤 변수를 참조해야할 것인지** 결정한다. 
  - 따라서 스코프를 JS 엔진이 식별자를 검색할 때 사용하는 **규칙**이라고도 할 수 있다. 
**결과**
- 1번과 2번의 x는 이름이 동일한 식별자이지만 스코프가 다른 **별개의 변수**다!
    - 1번 출력 ('`local`') : foo 함수 내부에서 선언된 변수 x는 지역 변수이다. 함수 내부에서 x를 호출하면 전역 변수보다 지역 변수를 우선적으로 참조하게 된다. 
    - 2번 출력 ('`global`') : 함수 외부(전역)에서 x를 호출하면, 함수 내부의 지역 변수에는 접근할 수 없기 때문에 **전역변수** x를 참조한다. 

> 식별자는 어떤 값을 구별할 수 있어야 하므로 유일해야한다! 즉, 하나의 값은 하나의 유익한 식별자에 연결되어야 한다. 
- 하지만, 우리가 컴퓨터 사용할 때에도 하나의 파일 이름만 사용하지 않는데, 컴퓨터에도 폴더(디렉터리)라는 개념이 있기 때문이다.
- 즉, 스코프는 네임스페이스다. 

#### var 키워드로 선언한 변수 vs let이나 const 키워드로 선언한 변수 
- `var` 키워드는 동일한 스코프 내에서 여러 번 선언해도 에러가 발생하지 않고, 마치 값이 재할당되는 것처럼 동작한다.
```js
function foo() {
  var x = 1;
  var x = 2;
  console.log(x); // 2
}
foo();
```

- 현대적인 자바스크립트 방식인 `let`이나 `const`는 중복 선언 시 즉시 에러를 발생시켜 실수를 방지해 준다.
```js
function bar() {
  let x = 1;

  let x = 2; // SyntaxError: Identifier 'x' has already been declared
}
bar();
```

## 13.2 스코프의 종류 

```js
// [전역 스코프]
var x = "global x";
var y = "global y";

function outer() {
  // [outer 함수 지역 스코프]
  var z = "outer's local z";

  console.log(x); // ① global x (전역 변수 참조)
  console.log(y); // ② global y (전역 변수 참조)
  console.log(z); // ③ outer's local z (자신의 지역 변수 참조)

  function inner() {
    // [inner 함수 지역 스코프]
    var x = "inner's local x";

    console.log(x); // ④ inner's local x (자신의 지역 변수 참조)
    console.log(y); // ⑤ global y (전역 변수 참조)
    console.log(z); // ⑥ outer's local z (상위 스코프인 outer의 지역 변수 참조)
  }

  inner();
}

outer();

// [전역 스코프]
console.log(x); // ⑦ global x (전역 변수 참조)
console.log(z); // ⑧ ReferenceError: z is not defined (지역 변수 z에 접근 불가)
```

- 코드는 전역과 지역으로 구분할 수 있고, 변수는 자신이 선언된 위치에 의해 자신이 유효한 범위인 스코프가 결정된다. 

| 구분 | 설명 | 스코프 | 변수 |
| :--- | :--- | :--- | :--- |
| 전역 | 코드의 가장 바깥 영역 | 전역 스코프 | 전역 변수 |
| 지역 | 함수 몸체 내부 | 지역 스코프 | 지역 변수 |

### 전역 스코프
- 전역 : 코드의 가장 바깥 영역 
- 전역 변수는 어디서든지 참조할 수 있다 

### 지역 스코프 
- 지역 : 함수 몸체 내부 
- 지역 변수는 자신의 지역 스코프와 하위 지역 스코프에서 유효하다. 

## 13.3 스코프 체인 
- **함수의 중첩** : 함수 몸체 내부에서 함수가 정의된 것 
  - 중첩 함수(rested function) : 함수 몸체 내부에서 정의한 함수
  - 외부 함수(outer function) : 중첩 함수를 포함하는 함수 


[ 전역 스코프 ]

| 식별자 | 값 |
| :--- | :--- |
| x | "global x" |
| y | "global y" |
| outer | `<function object>` |

 ▲ (상위 스코프 참조)

[ outer 지역 스코프 ]
| 식별자 | 값 |
| :--- | :--- |
| z | "outer's local z" |
| inner | `<function object>` |

▲ (상위 스코프 참조)

### [ inner 지역 스코프 ]
| 식별자 | 값 |
| :--- | :--- |
| x | "inner's local x" |
---

- 스코프 체인 : 스코프가 계층적으로 연결된 것. 
- 위 그림에서 스코프 체인은 전역 스코프, `outer` 함수의 지역 스코프, `inner` 함수의 지역 스코프로 이루어진다. 

- **변수를 참조할 때 JS 엔진은 스코프 체인을 통해 변수를 참조하는 코드의 스코프에서 시작하여 상위 스코프 방향으로 이동하며 선언된 변수를 검색한다!**

  - 스코프 체인은 물리적인 실체로 존재한다. JS 엔진은 코드를 실행하기에 앞서 위 그림과 유사한 자료구조인 렉시컬 환경을 생성한다. 
  - **렉시컬 환경** : "현재 위치에서 어떤 변수를 쓸 수 있지?"를 파악하기 위해 만든 '변수 지도'

- JS엔진은 스코프 체인을 따라 상위 스코프 방향으로 이동하지만, 절대 **하위 스코프로 내려가면서 식별자를 검색하는 일은 없다**. 
  - 상위 스코프에서 유효한 변수는 하위 스코프에서 자유롭게 참조 O
  - 하위 스코프에서 유효한 변수를 상위 스코프에서 참조 X 

```js
// 전역 함수
function foo() {
  console.log('global function foo');
}

function bar() {
  // 중첩 함수
  function foo() {
    console.log('local function foo');
  }

  foo(); // local function foo
}

bar();
```

> 스코프 : **식별자를 검색하는 규칙** 이라고 정리하면 굿

## 13.4 함수 레벨 스코프 (var 키워드의 당황스러운 특징 .. )
> 지역은 함수 몸체 내부를 말하고 지역은 지역 스코프를 만든다고 했는데, 이는 결국 지역 스코프는 **코드 블록이 아닌 함수에 의해서만** 생성된다는 의미이다! 

```js
var x = 1;

if (true) {
  var x = 10; // var 키워드로 선언한 변수 x는 전역변수이다. 
  // 이미 선언된 전역 변수 x가 있으므로 x 변수는 중복 선언된다.
  // 의도치 않게 변수 값이 변경되는 부작용을 발생시킴.
}
// if문 뿐 아니라 for문 while문도 마찬가지

console.log(x); // 10
```
-  var 키워드로 선언된 변수는 함수의 코드 블록(함수 몸체)만을 지역 스코프로 인정한다.
- 함수 밖에서 var 키워드로 선언된 변수는 코드 블록 내에서 선언되었다 할지라도 **모두 전역 변수**다.

> `let`, `const` 키워드는 블록 레벨 스코프를 지원한다. (15장에서 계속)

## 13.5 렉시컬 스코프

```js
var x = 1;

function foo() {
  var x = 10;
  bar();
}

function bar() {
  console.log(x);
}

foo(); // ?
bar(); // ?
```

> 실행 결과, 둘 다 `1`이 나온다. 이를 이해하기 위해 JS가 **동적 스코프**를 따르는지, **렉시컬 스코프**를 따르는지 알아야 한다. 

**동적 스코프** 
> 함수를 어디서 호출했는지에 따라 함수의 상위 스코프를 결정한다.
- `bar` 함수의 상위 스코프는 `foo` 함수의 지역 스코프와 전역 스코프일 것이다. 
- 함수가 호출되는 시점에 동적으로 상위 스코프를 결정해야 한다. => 동적 스코프

**렉시컬 스코프** 또는 **정적 스코프** 
> 함수를 어디서 정의했는지에 따라 함수의 상위 스코프를 결정한다. 
- bar 함수는 **전역에서 정의** 되었다. 따라서 bar가 `foo` 안에서 호출되든, 어디서 호출되든, `bar`가 기억하는 상위 스코프는 언제나 **전역 스코프**이다. 

- 동적 스코프 방식처럼 상위 스코프가 동적으로 변경x, 함수 정의가 **평가되는 시점**에 **정적으로 결정**된다. 

  - js를 비롯한 다양한 프로그래밍 언어가 렉시컬 스코프를 따른다. 

#### 정리
-  함수의 상위 스코프는 언제나 자신이 **정의된 스코프**다. 
- 함수 정의(함수 선언문 또는 함수 표현식)가 실행되어 생성된 함수 객체는 언제나 **함수 정의가 실행될 때 정적으로 결정된 상위스코프**를 기억한다. 
  - 함수가 호출될 때마다 함수의 상위 스코프를 참조할 필요가 있기 때문이다!
